# 小米音箱 → 自定义模型 → 智能家居

把已有音箱变成自定义模型的语音入口，按现场证据选择可行路径。这里的已验证路线是：**小爱唤醒和小米云识别 → 新鲜转写 → 模型原生工具 → Home Assistant → 原音箱播报**。不需要额外说一次“贾维斯”。

这是一次 S12、Mac 常驻桥、树莓派 Home Assistant 和 Aqara M2 实践提炼出的 Skill，附可运行参考代码。它没有取得音箱 root，没有读取原始麦克风 PCM，也没有完全禁用小米 NLU。其他型号先做能力探针，不能直接移除型号校验。

## 从当前阶段接着做

先读取现有项目说明、运行配置的字段结构和当前服务状态，避免重做已完成的配对或重放历史指令。凭据值留在私有文件中，不带入聊天或公开文档。记录以下最小状态，缺什么再查什么：

| 状态 | 必要证据 |
| --- | --- |
| 音箱身份 | 产品标签、LAN 地址、DID、MAC、内部 model、固件；哪些来自发现，哪些经过认证 |
| 凭据 | miIO token 与 `micoapi` 会话分别是否有效；只记录文件位置和权限 |
| 家居 | HA 是否真实可用，设备经何网关进入，目标实体与房间是否已核对 |
| 语音 | 当前主 ASR、云记录新鲜度、TTS 接收/起播/结束/听音各层证据 |
| 模型 | 提供商、当前配置、是否原生 tools、查询与控制的真实回执 |
| 常驻 | 进程、持久化 DB、旧任务、音量恢复方式、已有用户授权范围 |

详细步骤按需读，不必把所有参考文档一次载入：

1. **找设备、认型号、拿到合法凭据**：读 [01-discovery-and-auth.md](references/01-discovery-and-auth.md)。认证登录及手机扫码由账号持有人完成；已经取得的授权不重复索要。
2. **把网关和实体接入 HA**：读 [02-home-assistant-matter.md](references/02-home-assistant-matter.md)。优先保留现有 HomeKit 配对，用实际序列号与回路核对房间。
3. **接通识别和播报，再抑制原生回答**：读 [03-voice-and-audio.md](references/03-voice-and-audio.md)。先分别证明输入、输出可用，再验证静音门控。
4. **让模型理解并调用设备工具**：读 [04-agent-tools-and-execution.md](references/04-agent-tools-and-execution.md)。不要在模型之后重新用原句正则批准设备选择。
5. **安装参考实现**：读 [07-reference-runtime.md](references/07-reference-runtime.md)。代码在 [assets/runtime](assets/runtime)，示例值需要替换，不能直接控制示例 IP。
6. **验收、常驻、恢复**：读 [05-operations-and-validation.md](references/05-operations-and-validation.md)。失败时按 [06-troubleshooting.md](references/06-troubleshooting.md) 的证据分层定位。

## 执行中的关键约束

- 依据已确认的型号和能力选适配器。端口 22 开放、miIO token 有效和取得 shell 是不同事实；没有恢复证据时不以“试试降级”替代验证。
- 对外设控制沿用本次用户授权。发现、只读检查、已授权配置和测试继续推进；账号身份认证、必须的实体按键或确实缺失的授权只暂停依赖它的步骤。不要继承本案例用户“不用备份”的选择到其他设备。
- 模型只接收设备目录和必要事实，不接收 HA token、小米会话或其他家庭设备数据。凭据文件位于 Git 之外，私有文件 `0600`、目录 `0700`。
- 一条语音先登记身份与输入 ID，再规划。只处理绑定设备的新鲜最终转写；启动建立基线，不执行历史；同 ID 不重发模型、HA 或 TTS。
- 将**语义判断**与**执行权限**分开：模型理解否定、房间类别、建议与委托；程序验证真实实体、动作能力、参数、身份、时效和取消。不要通过删权限校验获得“泛化”。
- 一批动作全部验证、持久化后再发出。请求结果未知时记 `uncertain`，查询状态和诊断，不自动重放有副作用的操作。
- 新输入可取消旧提案和尚未发出的动作，无法撤销已发出的物理动作。停止播报必须不等待模型网络请求。
- 原生小爱仍会理解语音，且可能执行自己绑定的设备。音量门控只管理共享播放声音，不代表小米逻辑已经关闭；播报窗口中重新唤醒也可能出现原生声音。
- 明确区分 `mock_applied`、HA `applied`、TTS `accepted`、实际播放监测和现场听音。回执被接收不等于用户听见。

## 交付什么

完成时给出当前架构、脱敏身份与实体映射、可复用配置位置、启动/停止方式、真实工具调用与设备回读结果，以及没有验证的边界。保留本地诊断记录，公开时只提炼必要结论。

最小验收包括：房间类别命令、具体设备命令、否定不执行、建议不执行、明确委托的事实依据、重复 ID 不重放、过期和后续输入取消、部分失败不假报成功、长批次有短播报、正常退出恢复音量，以及至少一次实际麦克风到可听反馈的现场测试。没有现场条件时明确报告缺的这一层，不把合成转写当成真人麦克风验收。

原案例后期有两条窗帘语音失败，随后回放和主入口验证正常，但旧日志无法归因；这项限制必须保留。参考实现已增加脱敏模型错误日志，仍不是所有型号、固件和网络环境的稳定性承诺。
